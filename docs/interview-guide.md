# 客户访谈提纲（第 1—45 天）

用途：验证问题是否真实，**不是**让受访者评价产品创意。每次访谈记录日期、角色、是否展示材料、后续动作；不要把推测写进事实栏。所有材料必须脱敏，不收集客户代码或个人信息。

## 开场（2 分钟）

说明：我们在研究团队如何为一次发布准备说明材料。不推销、不要求提供机密；可以展示脱敏后的目录/表格/截图。询问是否允许做匿名笔记。

## 核心问题（15—20 分钟）

1. 请回忆最近一次对外或内部正式发布：发布材料是谁整理的？
2. 能否展示当时的脱敏目录、表格、清单或截图？
3. 涉及哪些角色？各自大约花了多少时间？
4. 最近一次临时补材料或发现流程例外是什么情形？后来怎么补上的？
5. 如果这个问题不解决，会具体影响到什么（延期、返工、客户提问、审计发现）？
6. 谁拥有预算？采购需要经过哪些安全、法务或供应商步骤？
7. 发布事实目前存在哪里（GitHub、聊天、表格、工单、部署系统）？哪些能直接链接？
8. 如果要把这些东西交给第三方工具，最大的顾虑是什么？（不要引导到“我们的工具没有这个问题”）

## 收尾（3 分钟）

- 询问是否愿意进入固定范围试点讨论（1,500 美元/6 周），记录具体决策人和采购步骤。
- 记录可回访方式，仅保存受访者明确同意保存的联系方式。
- 明确说明：本次对话不是采购承诺，我们不提供审计认证。

## 访谈记录模板

```text
日期 / 角色 / 团队规模：
是否展示近期真实材料：是 / 否（材料类型，已脱敏）
最近一次发布材料整理者、耗时、涉及角色：
最近一次例外或补材料情形：
不解决的具体后果：
预算所有者与采购步骤：
有效访谈：是 / 否（判断依据）
下一步：无 / 试点讨论 / 回访（需明确同意）
```

## 阶段计数

- 第 1—14 天：约 50 个候选名单、20 次有效访谈。
- 第 14 天问题门：≥8 个团队展示近期真实流程，≥5 个团队愿意讨论试点范围、权限与采购。
- 计数只来自实际完成的对话；未完成的联系不计数，不写“预期会有”。
