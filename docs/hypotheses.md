# 待验证假设

所有假设初始状态均为 `未验证`。本文件不是结果记录：没有访谈、订单或收入数据时，**不得**把任何一行改成“已验证”。

| ID | 假设 | 验证方式 | 通过标准 | 不通过时的动作 | 状态 |
|---|---|---|---|---|---|
| H1 | 目标团队近期确实人工整理过发布材料 | 访谈中展示脱敏目录/表格/截图；不要求评价创意 | ≥8/20 个有效访谈展示近期真实材料 | 换客户细分或问题定义 | 未验证 |
| H2 | 整理工作涉及多个角色且花时间 | 访谈询问角色与耗时，要求具体最近一次案例 | 能给出角色、步骤与可估计工时 | 放弃“省工时”价值主张 | 未验证 |
| H3 | 关键缺口是“事实散落 + 无法复现”，而不是“缺少合规结论” | 让受访者展示最近一次补材料/流程例外 | 多数证据指向留痕与复现，而非要认证背书 | 重新定义产品定位 | 未验证 |
| H4 | 用户能在 15 分钟内用测试仓库跑通 CLI/Action 并看懂输出 | 计时的新用户演练，无作者协助 | ≥目标用户中的多数在 15 分钟内完成 | 简化上手路径，缩减字段 | 未验证 |
| H5 | JSON + Markdown 证据包足以进入采购/安全讨论 | 试点中让对方用产物 internally 说明流程 | 至少 5 个团队愿意具体讨论试点范围、权限与采购 | 调整交付形态，不建平台 | 未验证 |
| H6 | 团队愿意为固定范围试点支付 1,500 美元/6 周 | 发送固定范围报价，以**实际到账**为准 | 第 45 天 3 个已收款试点 | 复盘问题/客群/报价/采购 | 未验证 |
| H7 | 不同客户需求足够重复，值得自动化 | 统计试点中重复出现的配置、提醒、导出需求 | ≥2 个付费客户提出同一需求并愿付费 | 视为咨询业务或免费工具 | 未验证 |
| H8 | 本地/离线生成方式能过目标团队的安全审查 | 在试点中收集具体安全问题和权限清单 | 试点未被安全流程无限期阻断 | 缩小数据访问或调整部署形态 | 未验证 |

## 计数规则

- “有效访谈” = 实际对话且对方给出最近一次真实流程细节；已发送消息数不算。
- “真实材料” = 脱敏后的目录、表格或截图；口头泛泛描述不算。
- “付费” = 已收款；意向书、口头称赞、免费 PoC 与未收款订单都不算。
- “复用” = 在多个真实发布中主动再次生成，而非只交付一次样例。
